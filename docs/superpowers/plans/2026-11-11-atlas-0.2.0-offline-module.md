# Atlas 0.2.0 (own offline module) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Atlas keeps offline play in its own module (several offline names with skins and capes, a Profile tab), separates its accounts from the official launcher's, refuses Microsoft sign-in honestly, installs beside the official launcher, and says "Horizon Atlas" in its window, as four patches on upstream `launcher@0.2.59`.

**Architecture:** New code lives in Atlas's own files (`launcher/src/offline/` in the library, `launcher/src/atlas_*.rs` UI modules in the binary); upstream files get one-to-three-line seams. The game is started offline through `account::session_for_game`'s `GameSession.env` (`HORIZON_PLAYER_NAME`, `HORIZON_OFFLINE_SKIN`, `HORIZON_OFFLINE_SKIN_MODEL`, `HORIZON_OFFLINE_CAPE`), which every Horizon launch path applies.

**Tech Stack:** Rust (launcher workspace `launcher/`, GPUI, serde_json, image), GitHub Actions (ubuntu, windows, macos runners), PowerShell for the Windows end-to-end check.

**Spec:** `docs/superpowers/specs/2026-11-11-atlas-0.2.0-offline-module-design.md` (read it first; this plan argues from it).

## Global Constraints

- Base: `refs/upstream/tags/launcher@0.2.59`. Old offline code to port: `refs/upstream/tags/launcher@0.2.58` (read with `git show <ref>:<path>`).
- Work in a scratch clone outside the owner's repository (commits there are fine). Never commit to or push the owner's repository; the owner brings the branch in at the end.
- Final history: Atlas's existing commits, minus `patch: offline-play`, plus exactly four patch commits with these exact subjects: `patch: offline`, `patch: no-sign-in`, `patch: own-install`, `patch: branding` (the existing `patch: branding` gets the title change as a follow-up `atlas:` commit squashed into it, see Task 12), and `atlas: ...` commits for workflows and docs. No `Co-Authored-By` or "Generated with" lines.
- Atlas data: `<data_dir>/atlas/` where `data_dir()` is `horizon_launcher::backend::data_dir()`. Files: `atlas/accounts.json`, `atlas/account-secrets.json`, `atlas/offline.json`, `atlas/skins/<lowercase>.png`, `atlas/skins/<lowercase>.cape.png`, `atlas/windows-move-dismissed`.
- Never write, change or delete the shared `<data_dir>/accounts.json`, `<data_dir>/skins/`, worlds, saves or settings.
- Offline names: 3–16 characters, ASCII letters, digits or `_`, unique ignoring case. Skins 64×64 or 64×32 PNG; capes 64×32 or 22×17 PNG.
- Keychain service: `io.github.nezbut.horizon-atlas`. Windows: app name `Horizon Atlas`, uninstall key `Software\Microsoft\Windows\CurrentVersion\Uninstall\HorizonAtlas`, own key `Software\Horizon\Atlas`. Linux menu entry `horizon-atlas.desktop`, `Name=Horizon Atlas`. macOS bundle `Horizon Atlas.app`, `CFBundleIdentifier` `io.github.nezbut.horizon-atlas`, `CFBundleName`/`CFBundleDisplayName` `Horizon Atlas`; the bundle executable stays `Contents/MacOS/horizon-launcher`.
- Every user-facing string is a literal `tr("…")` or `trf("… {x} …", …)` with its key in all 86 `launcher/lang/*.json`, appended at the end of each file, translated, same `{placeholders}` in every language, no empty values.
- UI uses the launcher's own components and theme (glass and classic looks; light, dark, system appearance). No new visual style.
- Checks (all must pass at the end): `cargo fmt --manifest-path launcher/Cargo.toml --check`; `cargo clippy --manifest-path launcher/Cargo.toml --release --all-targets -- -D warnings`; `cargo test --manifest-path launcher/Cargo.toml --release --lib --bins --test owner_gate`; `uv run python -m unittest discover -s tests -p 'test_atlas*.py'`; `uvx --from actionlint-py actionlint .github/workflows/*.yml`. Use `CARGO_TARGET_DIR` outside the clone to share builds.
- The owner's rules: edit files with the editor (no `sed -i`, heredocs, inline scripts that write files), Python only as `uv run python`, short single-purpose shell commands.

## Decisions this plan adds to the spec (the owner sees them in the handoff)

- `play --account NAME` stays Microsoft-only: the CLI resolves `--account` through `Accounts::find` before any session, and Atlas's file has no Microsoft accounts in 0.2.0. Offline names are chosen with `horizon-launcher offline select NAME` or in the window.
- Java Edition instances (`backend::java_game` → `account::java_player`) stay owner-gated, as in Atlas 0.1.x; offline play is for Horizon.
- On Linux the account secrets also live in a file (`account-secrets.json` beside `accounts.json`), so it moves to `atlas/` with the accounts.
- Text inputs in the launcher are tied to `servers_page::Field`; the Profile tab's name field adds one variant there.
- The account chip shows the default head for an offline name (upstream's offline heads are gone).

## Review Focus

1. A 0.1.x player whose old `accounts.json` lists names whose skin files are missing, or whose `looks` names differ in case from `offline`: migration keeps every name, copies only files that exist, and never fails the start.
2. Renaming a name to one that differs only in case (`steve` → `Steve`) or removing the selected name: files follow the rename; removing the selected name selects the next name or nobody.
3. A Windows machine where the official launcher, not Atlas, is installed in `...\Programs\Horizon Launcher`, or whose old registry keys point at an official launcher elsewhere: the installer offers no removal and touches nothing there.
4. The self-updated 0.2.0 running from the old folder: `installer::after_update` must not create Atlas's new registry keys for that old install, and the one-time dialog appears once.
5. `install.sh` on macOS over a 0.1.x install (`~/Applications/Horizon Atlas/Horizon.app`): the old `Horizon.app` there is replaced by `Horizon Atlas.app`, not left beside it.
